# 三国杀小模型自对弈（Self-Play）训练参数方案 v1

> 适用对象：1~5M 参数 attention 小模型，非 VLM
> 游戏环境：无名杀（琉璃版）斗地主模式，34 将（标准包 33 + 裴秀）
> 硬件：RTX 4060 Laptop 8G 显存 / 16G 内存
> 前置：SFT 打底（当前约 1.2 万条，目标 2~3 万条）
> 阶段衔接：SFT → **自对弈（本方案）** → MCTS 搜索增强

## 1. 设计原则

1. **小模型路线：不要照搬 AlphaZero/ReBeL 的大搜索框架**。1~5M 参数模型的目标是当"快策略"，搜索留给第四阶段 MCTS；自对弈阶段只训干净的 PPO 策略+价值网络。
2. **对手质量决定上限（Opponent Bottleneck）**：纯自对弈会追逐自己尾巴。必须引入"固定强基准 + 历史检查点池 + 课程"。
3. **奖励以终局胜负为主**：三国杀是典型稀疏奖励；塑形必须极小且与胜负对齐，否则模型学会"刷分不赢"。
4. **信息缺失是硬上限**：手牌/身份/牌堆隐藏不可见，模型能学到的是"在给定信息下的最优反应"，不做对手手牌建模；身份部分用预测头缓解（参考超参数）。
5. **8G 显存 = 采样与学习分离**：GPU 只负责小批量学习，大量 CPU 线程并行跑无名杀环境采样。

## 2. 总体架构（采样器-学习者分离）

```
┌─────────────────────────────────────────────────────────┐
│                   自对弈训练循环                          │
│                                                         │
│  [CPU 采样池]  N 个无名杀环境实例（多进程并行）            │
│    每局 3 个席位：地主(AgentA) + 农民1(AgentB) + 农民2(AgentC)│
│    席位策略来自：策略池采样 / 固定基准 / 课程对手            │
│         │ 轨迹：状态序列 + 动作 + 掩码 + 回合奖励 + 终局     │
│         ▼                                                 │
│  [经验队列] queue buffer（先进先出，滚动窗口，不用 ring 覆盖）│
│         │                                                 │
│         ▼                                                 │
│  [GPU 学习者] PPO 更新（小批量多次 epoch）                  │
│         │                                                 │
│         ▼                                                 │
│  [策略池] 定期入池 → 按能力评分替换弱者                      │
│         │                                                 │
│         ▼                                                 │
│  [评估] 固定基准（琉璃版强AI）+ 策略池头部 + 历史冠军         │
└─────────────────────────────────────────────────────────┘
```

关键点：
- **席位策略配置**（一局的三个玩家）：
  - 地主席位 = 待训练策略（或策略池采样）；
  - 农民席位 = 策略池采样 / 固定基准 / 随机，与地主**不同策略**混合，防止纯双拷贝自对弈导致单策略崩溃；
  - 训练目标可以同时给地主视角和农民视角采样梯度（共享主干，角色特征区分）。
- **多进程采样**：无名杀是 Node.js 环境，建议用多进程（如 8~16 个 worker 进程，每个进程串行跑多局），轨迹统一汇入队列；单局几十回合，吞吐目标 ≥ 1 万步/分钟。
- **queue buffer**：经验队列固定容量（如最近 20 万步），新数据先进，旧数据自然流出；**不要用 ring buffer 覆盖**（ByteRL 实证 +10% 胜率）。

## 3. 算法选型与依据

**主选：PPO（Actor-Critic，共享主干 + 分离头）**

理由：
- 轻量级黄金标准研究里 TRPO 比 PPO 稳定（22.5% vs 15.0%），但 TRPO 二阶优化在 1~5M 小模型上计算开销占比过大、实现复杂；PPO 通过 **clip + KL 惩罚双保险** 近似信任区域，工程上足够；
- DouZero/ACM 卡牌自对弈均验证 PPO 系在斗地主/卡牌上的有效性；
- 若后期发现 PPO 剧烈震荡、遗忘严重，再切 TRPO 或加 KL 硬约束（本方案已在默认参数里内置 KL 目标）。

**备选：Deep Monte-Carlo（DouZero 风格 Q-learning）**
若 PPO 因动作空间巨大（技能+目标组合）训练不稳，可切换为 DouZero 的 DMC 管线作为对照实验。但用户已有 SFT 模型冷启动，PPO 更契合"策略网络直接复用"。

## 4. 核心超参数表（默认值 + 调参方向）

### 4.1 PPO 核心参数

| 参数 | 默认值 | 依据 | 调参方向 |
|---|---|---|---|
| clip ε | 0.2 | PPO 标准 / ACM 2026 | 震荡大 → 0.1；收敛慢 → 0.3 |
| GAE λ | 0.95 | 通用经验 / ACM 2026 | 方差大 → 0.9 |
| 折扣 γ | 0.99 | 通用起点；一局几十回合 | 若对局短（<20 回合）可提到 1.0（ByteRL 结论） |
| 学习率 lr | 3e-4（Adam） | 通用默认 / ACM 2026 | 小模型可 1e-3 起步配余弦衰减到 1e-4；不稳则降 1e-4 |
| critic lr | 与 actor 同 lr 或 3x（9e-4） | veRL 经验（critic 可更快） | 单独控制时 actor 3e-4 / critic 1e-3 |
| 更新轮数 epochs | 4 | 通用 3~10 | 数据量少 → 3；过拟合 → 减 |
| mini-batch | 2048 | 依队列容量取 1/10~1/20 | 显存允许可到 4096 |
| 熵系数 c2 | 0.01 起始 | 通用 | 过早收敛/钻固定套路 → 提到 0.02~0.05；后期衰减到 0.001 |
| 价值系数 c1 | 0.5 | 通用 | 价值头不稳 → 0.25 |
| 梯度裁剪 | 0.5（max grad norm） | 通用 | 梯度爆炸 → 0.3 |
| KL 目标 | 0.02（超过则提前终止本轮更新） | 替代 TRPO 的信任域 | 遗忘严重 → 降到 0.01 |
| 优势归一化 | 强制（mean/std + eps） | 实战铁律 | 始终开启 |
| GAE 序列长度 T | 每回合整局（或 128 步窗口截断） | 卡牌回合制天然分幕 | 按回合边界做 GAE |

### 4.2 网络结构（1~5M 参数预算）

| 模块 | 建议 | 备注 |
|---|---|---|
| 输入编码 | 特征张量：手牌/装备/判定/身份/牌堆/决策上下文 → 逐字段 embedding 拼接 | 与 SFT 输入编码保持一致，**直接复用 SFT 权重冷启动** |
| 主干 | 轻量 Transformer：`hidden=256, layers=4~6, heads=4~8, ffn=4x`（约 1.5~4M 参数） | 卡牌序列依赖强；黄金标准研究证明 MLP/Transformer 上限接近，主干不要堆过大 |
| 身份特征 | 身份 ID 作为条件 embedding 拼入主干（地主/农民），**共享主干+条件区分** | 比完全分模型省参数；ByteRL 分模型 +6.5% 可留作后期选项 |
| 身份预测头（可选） | 从公共信息预测"其他玩家身份/身份组合"的辅助头，与价值头并联，预测 loss 加 0.1 权重 | 参考超参数三国杀身份预测；斗地主地主明、农民隐藏时很有价值 |
| 策略头 | 动作分类（基础动作类别）→ 与目标/技能组合 → **合法动作掩码**强制 | 动作空间大，掩码必须做，DouZero 关键经验 |
| 价值头 | 单标量（地主视角或本席视角） | 视角对齐：以"当前玩家身份"的胜负计 |

> 参数量自检：256 宽 4 层 Transformer ≈ 1.5M；512 宽 6 层 ≈ 5M。建议 256/4~6 层起步，验证信息上限后再扩。

### 4.3 采样与队列

| 参数 | 默认 | 说明 |
|---|---|---|
| 并行环境数 | 8~16（CPU 进程） | 8G 卡只跑学习，采样全在 CPU |
| 队列容量 | 200k 步（queue buffer） | 滚动窗口，新数据优先 |
| 每局最长回合 | 60~80 回合封顶（强制终止按价值判分） | 防挂机拖局 |
| 种子 | 每局随机 | 保证探索覆盖 |

## 5. 奖励设计（防钻空子）

**核心奖励 = 终局胜负**（稀疏、对齐目标）：

| 事件 | 奖励 | 说明 |
|---|---|---|
| 地主胜利 | 地主席 +1.0；两农民席 -1.0 | 零和 |
| 农民胜利 | 两农民席各 +1.0；地主席 -1.0 | 农民共享胜利 |
| 平局/超时 | 0（或按残血/牌差微小 ±0.05） | 尽量少用 |

**可选塑形（必须与胜负严格对齐，权重极小）**：

| 事件 | 奖励 | 风险控制 |
|---|---|---|
| 每回合步罚 | -0.001 | 防无限拖局；若模型变"刷步数"，直接去掉 |
| 击杀/濒死 | ±0.05 | 中间信号，但可能诱导"只收人头不赢"，权重 ≤0.05 并配合终局验证 |
| 血差 | 每回合结束 ±0.01×血量差 | 同上，若与胜率负相关立即移除 |

**防钻空子硬规则**：
1. 塑形奖励总权重 ≤ 终局奖励的 5%，且只做评估参考、**不以塑形驱动梯度主方向**（黄金标准研究：密集塑形导致短视"点农"，明确失败）；
2. 每 N 轮用纯胜负版评估当前策略 vs 固定基准，若塑形版胜率不升反降，说明塑形在钻空子 → 削减；
3. 不允许奖励"使用某技能次数/牌型完成度"这类与胜负无因果的项。

## 6. 对手调度（策略池 + 课程）

**三层对手来源（按概率混合采样）**：

| 对手来源 | 默认占比 | 说明 |
|---|---|---|
| 当前策略（自对弈） | 50% | 两个席位都用最新策略（可加 ε 扰动） |
| 历史检查点池（近 16~32 个） | 30% | 池内按"新近权重高"采样；防单策略崩溃/遗忘 |
| 固定基准 / SFT 冷启动模型 / 随机 | 20% | 随机可逐步降低到 5%；固定基准仅评估不训练 |

**课程进度（参考黄金标准研究）**：
- 阶段 A（0~10% 步数）：对手以随机 + SFT 模型为主，学基础合法性；
- 阶段 B（10%~60%）：历史检查点池为主 + 自对弈混合；
- 阶段 C（60%~100%）：自对弈 + 池，固定基准占比最低。

**策略池维护（ACM 2026 范式）**：
- 每 5k~10k 步把当前策略快照入池；池容量固定（16~32）；
- 淘汰规则：定期跑"池内循环赛"，胜率垫底者出局（胜率替换）；
- 评估时用**池内头部 + 固定基准 + 上赛季冠军**三方基准，避免"只赢自己"的假象。

**热启动（Warm Starting）**：每次策略池新一轮迭代，从上一轮"最佳检查点"继续训练，而不是从零（黄金标准研究实证有效）。

## 7. 非完美信息处理（身份与隐藏牌）

1. **状态编码只含公共+私人可见信息**：自己的手牌/装备/判定全量可见；对手只给手牌数/装备面/已出牌记录/身份相关公开信息；牌堆只给剩余数（不泄漏）。
2. **斗地主身份**：地主明身份；农民之间按无名杀规则（明/暗）处理——暗农民不能确定队友身份。方案：
   - 状态里带"本席身份 + 已公开身份"；
   - 启用**身份预测辅助头**（§4.2）：从公共行动历史预测其他席身份分布，预测概率拼入主干输入，学"伪装/识别队友"（超参数已验证该思路）；
   - 训练时可用真实身份做辅助监督，测试/评估时只用预测。
3. **确定性化（可选，不推荐自对弈阶段使用）**：IS-MCTS 的"隐藏牌重发"思想留给第四阶段 MCTS；自对弈阶段网络直接吃信息集合特征即可（黄金标准研究：公平 ISMCTS 反而弱于训练好的反应式智能体）。

## 8. 训练基础设施（RTX 4060 8G 落地）

| 资源 | 分配 |
|---|---|
| GPU | 只跑学习：mini-batch 2048，1~5M 模型前向+反向 < 2G 显存，余量充足；可同时挂 1~2 个推理实例做评估采样 |
| CPU | 16 进程跑无名杀环境采样（Node 多进程），每进程 1 局串行 |
| 内存 | 16G：队列 200k 步 + 16 进程环境，预留 4~6G 余量 |
| 日志 | 每 1k 步记录 loss/entropy/kl/胜率；每 5k 步评估一次（对琉璃版 AI 100 局） |

**预期节奏**（粗估）：
- 单局约 30~60 回合，16 进程 ≈ 500~1000 局/小时；
- 目标自对弈总步数 100 万~300 万步（≈ 2~4 天可跑完主体）；
- 每 50k 步做一次"对固定基准 100 局"评估，胜率曲线决定是否提前停止。

## 9. 评估协议（防自欺）

1. **固定基准**：琉璃版强 AI（无名杀自带）作为固定标尺，**只评估、绝不参与训练**（黄金标准研究核心教训：与随机对打 99% 胜率、与自己对打永远平局，都不能说明强度）；
2. **三方评估**：每 5k 步跑三组各 100 局：vs 琉璃版强AI、vs 策略池头部、vs 上一冠军；
3. **胜率门槛**：只有 vs 琉璃版强AI 胜率 ≥ 60%（地主/农民分角色统计）才进入 MCTS 阶段；
4. **Elo 记录**：给池内所有策略建 Elo，跟踪是否有"循环克制"（A>B>C>A），循环出现 → 加大池容量/对手混合比例。

---

## 10. 与第四阶段 MCTS 衔接

1. 自对弈产出：`best_checkpoint.pth`（策略+价值双头）；
2. 价值头直接作为 MCTS 叶节点评估器；策略头作为先验（PUCT 的 P(s,a)）；
3. MCTS 阶段不再需要大规模自对弈采样，转为"少量搜索增强自对弈"（每步 MCTS 数十~数百次模拟）在推理端做；
4. 保留自对弈阶段的**策略池**，MCTS 阶段可与池内历史策略混战，防搜索策略被针对。

## 11. 避坑清单（调研实证踩过的坑）

| 坑 | 规避 |
|---|---|
| 纯自对弈 → 策略崩溃/遗忘 | 历史检查点池 + 课程 + 热启动（黄金标准研究实证有效） |
| 密集奖励塑形 → 刷分不赢 | 塑形 ≤5% 权重，只与胜负对齐（研究实证失败项） |
| ring buffer → off-policy 漂移 | queue buffer 滚动窗口（ByteRL +10%） |
| 无优势归一化 → 梯度震荡 | 强制 mean/std 归一化 |
| 无动作掩码 → 大量非法动作浪费 | 合法动作掩码强制（DouZero 关键） |
| 模型容量迷信 → 堆参数 | 1~5M 足够，信息缺失才是上限；先 256/4 层跑通 |
| 折扣 γ 太小 → 短视 | 一局几十回合，γ 0.99~1.0 |
| 用琉璃版 AI 参与训练 | 只评估不训练，防止模型过拟合单一对手套路 |
