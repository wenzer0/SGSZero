## 陷阱 7：跨代评估换牌，加对数压不掉

**现象**：`eval_vs_rule(..., seed0 + gen, ...)`，而评估内每副牌是
`random.Random(seed * 10000 + pair)`。5 代 = 5 批完全不同的牌。

**实测量**：44.3 / 48.0 / 48.0 / 47.3 / 44.0 被读成「横盘」；
实际上代与代之间混着牌力方差，趋势判据根本没测准。

**为什么 600 对救不了**：把 300 → 600 对只把二项噪声从 ±5.7pt 压到 ±4.0pt，
压不掉「每代换牌」这个系统性方差。跑 6000 对也一样。

**修复**：
```
所有代 + eval-only 基线固定同一 seed0
eval 返回逐 pair 的 win 列表（不是总胜率）
判据改成跨代配对：gen_k − gen_0 的配对 diff + CI，5 点做线性斜率
斜率 CI 下界 > 0 才算「随代数上升」
```
实测改后：斜率 -0.23 ± 0.58 pt/代、gen4−gen0 -1.3pt（CI 全负区间内），
「无增益」这次才是干净的。

## 陷阱 8：护栏自比 → 恒真（本项目最彻底的一次假通过）

**现象 A（ρ 自比）**：
```python
for sel_logs, z in game_logs:
    ... opt.step()                      # 本代训练完成
prev_net = copy.deepcopy(qnet)          # 训练【之后】才复制
qc = qnet(...); qp = prev_net(...)      # 同一份权重
rho = spearman_rho(qc, qp)              # 必然 1.0000
```
62 个状态 × 5 代，ρ 每代精确 1.0000、连小数都不动 —— 不是「排序稳」，是 A 和自己比。
修法：`gen_start = deepcopy(qnet)` 放在 `for gen` 之后、任何 `opt.step()` 之前。

**现象 B（loss 护栏恒等式）**：`w = max(A,0) ≥ 0`、`CE ≥ 0` ⇒ `loss = w·CE ≥ 0`
是数学恒等式。`if mean_loss < 0: exit(4)` 永远不触发，
「loss 恒正 ✅」证明不了「无界项没漏网」。

**现象 C（held-out 全 mask）**：早期护栏只造 1 个状态，且 `legal_mask` 只有 pass 槽 =1，
其余 24 槽被 `masked_fill(..., -1e9)` 填成并列常数 —— 25 路排序被钉死，ρ 恒 1。
修法：≥40 个真实决策状态、按 `compute_legal_mask` 逐个构造、报 ρ 均值与最小值。

**判据**：任何护栏先回答「它在什么情况下会失败」。恒真/恒假的护栏等于没有护栏。

## 陷阱 9：符号写反 / 目标无下界（同一家族，出现三次）

| 版本 | 形式 | 真实行为 |
|---|---|---|
| R1 | `(-z)·CE` | 赢局压 chosen、输局抬 chosen = 主动学输（48% → 10.7%） |
| R2 | `(+z)·CE` | 方向对了，但输局 `-CE` 下界负无穷；正侧自限、负侧越压越有力 → 全部 logit 系统性下移 |
| 候选公式 | `-A·log(1-π_a)`（A<0） | 数值验证：π→1 时 loss → -∞，且最小化会**抬高**输局动作 |

**修复**：负侧有界形式应为 `A·log(1-π_a)`（A<0 时为正、下界 0、最小化压低 π_a）。

**硬断言（比任何输出量级比较都可靠）**：
```
单步梯度符号：赢局 d(loss)/d(q_chosen) < 0（下降抬 chosen）
              输局 > 0（下降压 chosen）
失败直接 exit，不看 loss 曲线
```

**判据**：目标函数先查两件事 —— 方向（单步梯度符号）、有界性（数值扫 π→1）。
不要靠「loss 在降」判断训练健康：`-CE` 无下界时 loss 一路虚降，模型却在崩。

## 陷阱 10：锚构造错位 → 对手自己瓦解，被误读成「策略变强」

**现象**：三锚里的 `v6` / `gen` 锚把**只训过地主视角的 QNet** 拿去给农民出牌
（`_snapshot(game, p)` 里 `[SELF]` 变成农民）。分锚胜率显示 v6/gen 从 64%→79%、
rule 锚横盘，被读成「策略在弱锚上越学越强 = 自我克隆坐实」。

**实测量（300 对同牌零训练检验）**：
```
A: v6 锚当农民 vs 规则地主   农民胜率 31.3% ± 5.2
B: 规则 AI 当农民 vs 规则地主 农民胜率 53.3% ± 5.6
A−B = -22.0pt，CI [-29.7, -14.3] 显著
```
**真相是农民锚自己在瓦解，不是策略变强。** 整组「分锚胜率」作废。

**判据**：任何「对手池 / 强度梯度」在用之前，先做锚有效性 A/B 检验
（该锚作为对手 vs 稳定基线对手，同牌 300 对）。差 >10pt 即锚无效。

**附带教训**：`RuleAI` 的唯一强度旋钮 `aggression` 只在 `need=='sha'` 一个响应分支生效，
作用面极窄。「保三锚梯度」这种说法在测过梯度存在之前不成立。

## 陷阱 11：门控丢负样本 + 全局 baseline 混锚

**现象**：
```python
z = ±1
b = statistics.mean(zs)          # 全局，不分锚
w = max(z - b, 0)                # 输局整局丢弃
if w <= 0: return None, 0
```
- 所有赢局权重**完全相同**（`1-b`），赢一局硬锚和赢一局软锚学一样多
- 200 局/代里只有 65–88 局进梯度（单锚实测），每局只有 1 bit 胜负信息
- `b` 随赢率漂移：+0.25 → -0.35，赢局权重 0.75 → 1.35，形成
  「赢率↓ → b↓ → w↑ → 梯度更猛 → 赢率↓」的退化正反馈
- 三锚胜率差异极大（rule ~43%、v6 ~79%、gen ~72%）时，全局 `b` 把梯度偏向弱锚

**第 4 条该测的是「有效样本量 + 按锚拆分」，不是「回报方差」** ——
`z` 离散 ±1、赢局权重恒定，这套门控下几乎没有回报方差可谈。

**修复方向**：分锚 baseline（`b_k` = 该锚内 z 均值）、零手写 shaping；
或让输局信号以有界形式回来。

## 陷阱 12：小样本分锚当趋势

**现象**：每代 200 局按三锚拆开，每锚约 67 局。67 局的二项 CI ≈ **±12pt**。

```
rule  43.3 → 50.7 → 36.4    （掉 7pt，噪声内）
v6    64.2 → 78.8 → 79.1    （涨 15pt，勉强出单格，两格联合仍不稳）
gen   60.6 → 64.2 → 71.6    （涨 11pt，噪声内）
```

用它当「关键判读输入」下「自我克隆坐实」的结论，功效严重不足。

**判据**：分锚胜率每格 N ≥ 300（评估口径、argmax、同牌固定 seed），
必须报 N 与 CI（缺一不收）。训练局分锚 ≠ 评估局分锚（前者带 ε 探索、在线权重）。

## 陷阱 13：代内 ρ 冒充累计 ρ

**现象**：护栏 ρ 比较的是 `gen_start`（本代初）vs 代末，**每代重新存**。
5 代各自 ρ≈0.9992 ≠ gen4 相对 gen0 的 ρ；小变化会累积。

**逻辑自检**：若 argmax 排序真的一代都没变，部署行为就不会变，
胜率不可能 CI 全负地掉 8.5pt。二者只能有一个成立 —— 出现这种矛盾，
先怀疑测量口径，不要先建理论。

**判据**：护栏（代内 ρ）与策略测量（累计 ρ，gen_k vs gen0）分开报，
标注各自比较对象。护栏只防发散，不作有效性证据。

## 陷阱 14：确定性重算冒充独立复现

**现象**：固定 `pickC` 随机种子后，两次「独立全量」日志逐字节相同
（`collect=2053 snap=1979 trials=183`，连 `pickC` 都一样）——
是确定性重算，不是独立复现。固定漂移源是对的，但固定之后跑一万次也必然同号。

**同类**：A/A 100% 只验证同一份代码内的确定性，验证不了跨版本正确性
（11/05 那次 A/A 100% 验证的是「固定出第一张牌」的坏策略）。

**协议修正**：
```
「跨运行独立」必须换一批状态或换 seed 集，不是同一批确定性重跑
代理量结论必须与同对照的整局配对结果对账，方向冲突时以整局配对为准
```

## 汇总：现在新增的三道前置检查

在 [标准 v1](评估协议-标准.md) 的三道之外，改训练目标或护栏后追加：

1. **单步梯度符号断言**（赢抬输压，失败 exit）—— 优先级高于任何输出量级比较
2. **有界性数值扫描**（π→0 / π→1 两端，loss 不得趋于 ±∞）
3. **护栏可失败性检查**（回答「它在什么情况下会触发」；恒真/恒假即判无效）

**外加一条元规则**：任何自动判读文字必须与同屏数值可机械核对。
本项目三次出现脚本打印「非纯惩罚，有正向空间」而实际 `max=0.000 / mean=-0.022`、
「单类崩溃」而实际是候选数混杂 —— 自动结论分支应改为只报数值、不输出方向动作建议。
