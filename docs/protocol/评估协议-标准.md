# 评估协议标准（v1，2026-11-05 起生效）

> 任何写进 README、论文、结果文档的胜率数字，必须符合本协议。
> 制定背景见 [`评估协议-六个陷阱.md`](评估协议-六个陷阱.md)。

---

## 1. 六项必报（缺一不可）

| 项 | 要求 |
|---|---|
| 胜率 | 绝对值 **± 95% CI**，不能只报百分比 |
| 样本量 | 局数、配对数，明确写出 |
| 温度 | `tau=0`（argmax，默认）或 `tau>0`（采样，须说明理由） |
| max_rounds | 轮数上限，以及 stall 判罚规则 |
| stall 率 | 总胜率 / 剔除 stall 后胜率 / stall 率，三个数一起报 |
| A/A | 本次 harness 的 A/A 一致性，以及健全性检查结果 |

**禁止**：
- 用训练窗口累计胜率做版本间比较
- 报 `diff` 而不报两侧的绝对胜率
- 写"打赢 / 超越"，除非 CI 不含 0

---

## 2. 配对设计

```
for seed in range(N):          # N >= 300
    a = play(policy_A, seed)   # 同一副牌
    b = play(policy_B, seed)
    diff.append(b_win - a_win)
# 报 mean(diff) 与其 CI，而不是两个独立百分比之差
```

**为什么配对**：牌局初始运气（发牌）是主要方差来源，同牌双跑能把它抵消掉。

**前提**：引擎与策略的随机性必须全部由 `seed` 决定。禁止 `torch.multinomial`、`random.choice` 等全局 RNG 出现在决策路径中——它们不受 `deepcopy` 控制（见陷阱 4）。

---

## 3. 每次改评估 harness 后的三道前置检查

```
① A/A：同一策略双跑，要求 100% 一致（胜率、赢局数、均轮、stall 全相同）
② nan 防呆：assert not torch.isnan(probs).any()
③ 健全性：打 3-10 局人工看出的牌，确认不是"固定出第一张"这类退化
```

**三道全过，评估结果才可用于决策。** A/A 单独通过不够（陷阱 6）。

---

## 4. 判罚

```
max_rounds = 100
超过上限 → winner = 'fan'（地主未达成"杀光农民"的胜利条件）
```

**不允许按血量判地主赢**，否则 RL 会学会拖到上限。训练与评估必须使用同一个 `_resolve_stall()`。

---

## 5. 报告模板

```
评估模式：配对同牌双跑，N = 300 对
温度：tau = 0（argmax）
max_rounds：100，stall 判罚：一律农民赢
A/A：100%（含健全性检查）

| 版本 | 胜率 | 95% CI | stall 率 |
|---|---|---|---|
| A | 46.7% | ... | 1% |
| B | 48.0% | ... | 2% |

diff = -1.3pt，CI [-7.7, +5.1]，t = -0.41
结论：统计上无法区分（不写"超越"）
```

## 6. 口径变更须重测

改了以下任何一项，历史结论全部作废，必须统一口径重测：

```
tau / max_rounds / stall 判罚 / 采样方式 / 配对实现 / 动作空间 / 状态编码
```

**这条是四天里最贵的一课**：口径一变，之前所有"进步"都可能只是测量误差。
