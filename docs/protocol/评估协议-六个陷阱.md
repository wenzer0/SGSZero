# 评估协议：六个陷阱

> 记录 2026-11-02 → 11-05 期间，在 RL 阶段被实测数据逐个抓出来的评估口径问题。
> 每一条都曾推翻过一次结论。这份文档的目的不是复盘，是让下一个改动不再重演。
>
> 原则：**先证明尺子是对的，再相信读数。**

---

## 陷阱 1：累计口径 ≠ 终评口径

**现象**

训练时每 1000 局打印的 `wr_cum` 是从 ep0 一路累计的平均胜率，会包含早期差局。

**实测**

| 版本 | 训练窗口累计 | 独立终评（300 局） | 差 |
|---|---|---|---|
| v4 | 22% | 28.7% | +6.7pt |
| v5 | 27% | 31.3% | +4.3pt |
| v6 | 23% | 26.7%（配对口径） | +3.7pt |

**后果**：曾据"v4 22% → v5 27%（+5pt）"判定 n-step 有效，实际 v4 终评本来就 28.7%，净效果接近 0。

**修复**：跨版本比较只用**同一协议下的 checkpoint 终评**，训练窗口累计只用于监控进程是否健康，不用于任何结论。

## 陷阱 2：温度采样会掩盖价值函数缺陷

**现象**

`softmax(q/tau)` 采样引入的随机性，会把"某个动作的 Q 虚高"稀释掉，看起来反而更强。

**实测（同一批版本，两种口径）**

| 版本 | tau=0.1 采样 | tau=0 argmax | Q 极差 p90 |
|---|---|---|---|
| v4 | 28.7%（全场最高） | 13.3%（全场最低） | 5.1（reward 仅 ±2，明显膨胀）|
| v5 | — | 35.7% | 1.89（与 reward 匹配）|
| v6 | — | 48.0% | — |

**结论**：**argmax 是 Q 质量的探针**。Q 越膨胀，argmax 越差，而采样把它藏起来。这也意味着用采样口径画出的"平滑上升曲线"可能是假象。

**修复**：部署评估统一 `tau=0`（argmax）；采样只用于训练探索，不用于报告成绩。

## 陷阱 3：终局判罚与胜利目标不一致 → RL 钻空子

**现象**

引擎在 `roundNumber > max_rounds` 时按血量判胜：

```python
self.winner = 'fan' if farmer_total >= landlord_hp else 'zhu'
```

而游戏真实胜利条件是"杀光农民"。**于是"把农民打掉一点血、自己保血、拖到轮数上限"成了一条不需要棋力的稳赢路径**，训练里 `winner='zhu'` 直接给 `z=+2`。

**实测（100 对）**

| | stall 局 | 其中地主赢 |
|---|---|---|
| v5（无 pass） | 4% | 0 |
| v6（有 pass） | 3% | **3（全赢）** |

规模只有 3%，但方向是 0% → 100% —— **说明它被学会了，而且会随训练继续增长**。

**修复**：`_resolve_stall()` 改为 `self.winner = 'fan'`（没杀光就是没赢），训练与评估共用同一判罚；stall 率单独报告。修复后 300 对重测，stall 降到 1-2%、地主赢 0，`+7.3pt` 的 pass 增益原样保留（t 从 2.51 升到 2.70）。

## 陷阱 4：deepcopy 不复制全局 RNG → 假配对

**现象**

配对评估（同 seed 双跑）本应让两个策略面对完全相同的牌局，但 A/A 测试发现同一个策略两次结果不同。

```
A 跑 17.7%（53 胜）  /  B 跑 14.3%（43 胜）  → 差 3.4pt
```

**根因**：决策里有两处全局随机源，`deepcopy(game)` 只复制 `game.rng`（发牌/洗牌），复制不了它们：

```python
random.choice(legal_idx)              # 全局 Python random
torch.multinomial(probs, 1).item()    # 全局 torch RNG
```

**后果**：所谓"配对"只是初始 seed 相同，牌局中途就分叉了；方差削减远小于预期，**所有配对 CI 都被低估**。

**修复**：训练采样改用 `game.rng` 逆变换；评估改 argmax（无随机源）。修后 A/A 精确一致（diff +0.000，赢局数、均轮、stall 全相同）。

## 陷阱 5：tau=0 除零 → nan → 悄悄退化成"固定出第一张牌"

**现象**：改成 argmax 评估后，v5 胜率从 14-17% 掉到 7.3%，一度被误读为"贪心比采样差一半"。

**根因**

```python
qs    = q - q.max().clamp(min=0)
probs = torch.softmax(qs / self.tau, dim=-1)   # tau=0 → 负数 -inf，最大项 0/0=nan
...
chosen_idx = int(probs.argmax().item())        # 全 nan 时 argmax 返回 0
```

`probs` 全是 nan，`nan <= 0` 为 False，兜底分支被跳过，**策略固定出排序后的第一张牌**。

**修复**：argmax 直接对 `q` 取，不经过 softmax；删掉死代码；加 `assert not torch.isnan(probs).any()`。修复后 v5 真贪心水平 **35.7%**。

---

## 陷阱 6：A/A 100% ≠ 策略正确

**现象**：陷阱 5 那个坏策略，A/A 测试是**精确 100% 通过**的——因为它确实是确定性的。

**教训**：**A/A 只能证明"可复现"，证明不了"对"。** 确定性是正确性的必要条件，不是充分条件。

**修复**：A/A 之外，加一条健全性检查——让策略打 3-10 局，人工看它出的牌是否"像样"。固定出第一张牌这种错误，看 3 局就能发现，而 A/A 永远发现不了。
