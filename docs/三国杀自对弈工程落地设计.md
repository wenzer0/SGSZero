# 三国杀自对弈工程落地设计 v1

> 配套文档：《三国杀小模型自对弈训练方案.md》（超参数表 + 依据）
> 目标：把自对弈从"参数表"变成"能跑起来的代码结构"
> 原则：**采样在 Node（无名杀），学习在 Python（GPU），二者解耦**

## 1. 总体架构

```
┌─ 无名杀侧（Node.js / 16 进程并行）───────────────────────────┐
│  bot_selfplay.js（注入）                                     │
│    ├─ 跑局（test_game 全自动，抢在选将前设 _status.auto）      │
│    ├─ 决策点：打包状态 → HTTP 发 Python 推理服务 → 拿动作      │
│    ├─ 组装轨迹：状态/动作/掩码/奖励/终局 → 回传 Python 队列    │
│    └─ 每局完立即存盘（沿用 bot.js 教训）                      │
└──────────────┬──────────────────────────────────────────────┘
               │ HTTP / 轨迹流
┌─ Python 侧（GPU）───────────────────────────────────────────┐
│  a. 推理服务（fastapi/socket）：模型前向，返回掩码 softmax 动作 │
│  b. 经验队列（queue buffer，滚动 20 万步）                    │
│  c. PPO 学习者：小批量多 epoch 更新 → 定期广播新权重到推理服务  │
│  d. 策略池：快照入池 + 循环赛胜率替换                        │
│  e. 评估：vs 琉璃版强AI / 池头部 / 上冠军，各 100 局           │
└─────────────────────────────────────────────────────────────┘
```

**为什么采样放 Node 而不是 Python 重写环境**：你已有无名杀完整引擎（34 将、真实技能、真实规则），重写一个简化环境等于自废武功且工程量巨大；无名杀 `test_game` 已验证可极速全自动，直接复用。

## 3. 环境对接协议（最容易卡壳的部分）

### 3.1 JS → Python 推理请求（决策点触发）

JS 在每次 `choose*` 决策事件时，打包如下 JSON POST 到 `http://127.0.0.1:8001/predict`：

```json
{
  "seat_id": 0,
  "identity": "landlord",              // 地主/农民
  "state": {
    "hand": ["sha|A|spade", "shan|2|heart"],        // 手牌：牌名|点数|花色（与 dataset 同格式）
    "equip": ["zhugeliannu|q", "baxiu|h"],           // 装备区
    "judge": [],                                     // 判定区
    "opponents": [                                   // 对手只给公开信息（手牌数/装备/体力）
      {"hand_num": 3, "hp": 3, "max_hp": 3, "equip_face": ["sha_weapon"]},
      {"hand_num": 4, "hp": 4, "max_hp": 4, "equip_face": []}
    ],
    "deck_left": 35,                                 // 牌堆剩余
    "kind": "chooseToUse",                           // 决策上下文（同 dataset）
    "phase": "play"
  },
  "legal_actions": [                                 // 无名杀当前合法动作列表（掩码来源）
    {"action": "use", "card": "sha|A|spade", "targets": [1]},
    {"action": "use", "card": "sha|A|spade", "targets": [2]},
    {"action": "pass"}
  ]
}
```

### 3.2 Python → JS 响应

```json
{"action_idx": 2}    // 只回索引，动作本体 JS 端已有，不用传
```

### 3.3 轨迹回传

每局结束后 JS 把整局轨迹（步序列 + 每步奖励 + 终局胜负）POST 到 `/trajectory`，Python 写入队列；**每局完立即回传**（沿用"每 5 局存盘丢 80% 数据"的教训，改成每局即传）。

### 3.4 权重广播

学习端每次更新后，把新权重写入共享目录（或内存文件），推理服务热加载。**用版本号轮询**，避免加载一半的权重。

## 4. 状态/动作编码（与 SFT 完全对齐）

- **状态特征化**（`state_codec.py`）：手牌字段（牌名/点数/花色）用与 SFT tokenizer 相同的字典映射成 token 序列 → embedding → 拼接身份/装备/判定/牌堆/决策上下文特征。
- **关键铁律**：编码器必须与 SFT 阶段**逐字节一致**，否则 SFT 权重热启动失效（load_sft 权重名对不上直接报错，防隐性错位）。
- **动作空间**：`kind × 具体动作`。策略头输出动作类别分布，**合法动作掩码强制**（DouZero 关键经验）：`logits[mask==0] = -inf`，再 softmax。
- **身份特征**：身份 ID 作为条件 embedding 拼入主干；身份预测辅助头与价值头并联（预测 loss × 0.1）。

## 5. PPO 训练器核心骨架

```python
# src/rl/ppo.py（要点骨架，非完整实现）
class PPO:
    def __init__(self, model, cfg):
        self.opt = Adam([
            {"params": model.policy.parameters(), "lr": cfg.lr_actor},
            {"params": model.value.parameters(), "lr": cfg.lr_critic},  # critic 3x
        ])
        self.eps = cfg.clip_eps          # 0.2
        self.kl_target = cfg.kl_target    # 0.02，超限提前终止本轮

    def compute_gae(self, rewards, values, dones, gamma=0.99, lam=0.95):
        # 回合制分幕：按局边界计算，避免跨局污染
        adv = torch.zeros_like(rewards)
        gae = 0.0
        for t in reversed(range(len(rewards))):
            next_val = values[t+1] if not dones[t] else 0.0
            delta = rewards[t] + gamma * next_val - values[t]
            gae = delta + gamma * lam * gae
            adv[t] = gae
        # 铁律：优势归一化
        adv = (adv - adv.mean()) / (adv.std() + 1e-8)
        return adv

    def update(self, batch):
        for _ in range(cfg.epochs):            # 4
            for mb in batch:                    # mini_batch 2048
                ratios = exp(new_logp - old_logp)
                surr1 = ratios * mb.adv
                surr2 = clamp(ratios, 1-eps, 1+eps) * mb.adv
                policy_loss = -min(surr1, surr2).mean()
                value_loss = F.mse_loss(new_val, mb.returns)
                entropy_loss = -new_entropy.mean()
                loss = policy_loss + cfg.value_coef*value_loss - cfg.entropy_coef*entropy_loss
                loss.backward(); clip_grad_norm(0.5)
                self.opt.step()
            if kl > self.kl_target:             # 信任域保险
                break
```

**要点**：
- GAE 按局边界算（一局几十回合，跨局算会污染优势）；
- `old_logp` 在采样时冻结，更新期不重新算；
- 熵系数 0.01 起步，每 N 步衰减（如每 5 万步 ×0.5，到 0.001 停）；
- 价值头只对"当前玩家身份"的胜负负责（地主视角 / 农民视角分开算 return）。

## 6. 队列与策略池

```python
# src/rl/queue_buffer.py —— queue 滚动窗口（不用 ring，ByteRL +10% 经验）
class QueueBuffer:
    def __init__(self, capacity=200_000):
        self.buf = deque(maxlen=capacity)   # 新数据 append，旧数据自然流出

# src/rl/opponent_pool.py
class OpponentPool:
    def __init__(self, capacity=24):
        self.pool = []                     # 历史检查点（含元信息：步数/elo/胜率）
    def snapshot(self, model, step):       # 每 5k 步入池，超容量淘汰
        self.pool.append(model.state_dict())
        if len(self.pool) > self.capacity:
            self._eliminate()              # 循环赛垫底出局
    def sample(self, mode):                # 按课程概率采样对手
        # current 50% / history 30% / baseline 20%
```

**对手课程**（`curriculum.py`）：按全局步数占比切三段：
- A 段 0~10%：随机 + SFT 模型为主（学合法性）
- B 段 10%~60%：历史检查点池 + 自对弈混合
- C 段 60%~100%：自对弈 + 池，随机降到 5%

**热启动**：每轮迭代从"池内最佳检查点"继续，不从头训（黄金标准研究实证）。

## 7. 奖励注入（JS 端组装，Python 只收数值）

| 事件 | 奖励 | 由谁判定 |
|---|---|---|
| 地主胜 | 地主席 +1.0 / 农民席 -1.0 | JS 终局判定 |
| 农民胜 | 农民席各 +1.0 / 地主席 -1.0 | JS 终局判定 |
| 步罚 | -0.001/步 | JS 每步累加 |
| 击杀 | ±0.05 | JS 事件 |
| 超时 | 0（或按残血微小值） | JS 封顶 80 回合 |

**防钻空子**：塑形项权重 ≤ 终局 5%；每 5k 步用"纯胜负版"重评估一次，若塑形版胜率不升反降 → 砍塑形。奖励数值在 JS 组装成 `[{step, reward}, ...]` 随轨迹回传，Python 不自行构造。

## 8. 评估协议（防自欺）

每 5k 步三组各 100 局，**琉璃版强 AI 只评估、绝不参与训练**：
1. vs 琉璃版强 AI（分地主/农民角色统计胜率）；
2. vs 策略池头部（取 Elo 最高 3 个）；
3. vs 上一冠军。

里程碑：
- 动作一致率 ≥ 85%（SFT 验收，已接近）；
- vs 强 AI 胜率 ≥ 60% → 进入 MCTS 阶段；
- 全程 Elo 记录，出现 A>B>C>A 循环克制 → 加大池容量/混合比例。

## 9. 运行流程（从 SFT 到自对弈）

```bash
# 0. 前置：SFT 完成，产出 sft_best.pth（含策略头权重）
# 1. 热启动：load_sft 把 SFT 权重灌进 PPO 模型（价值头/身份预测头随机初始化）
python scripts/prepare_warm_start.py --sft sft_best.pth --out warm_start.pth

# 2. 起推理服务
python -m src.env.api_server --port 8001 --model warm_start.pth

# 3. 16 进程并行采样（无名杀侧）
for i in $(seq 1 16); do node bot_selfplay.js --id $i --server 127.0.0.1:8001 & done

# 4. 训练主循环（独立进程）
python -m src.train_selfplay --config configs/self_play.yaml
#   内部循环：收轨迹→攒 batch→PPO 更新→每 5k 步入池+评估→广播权重

# 5. 每 5k 步自动产出：metrics.json / 胜率曲线 png / elo.json / best_checkpoint.pth
```
