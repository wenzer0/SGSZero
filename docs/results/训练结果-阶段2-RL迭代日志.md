## v1：错误 reward（负结果基线）

- **配置**：erase 全-1 mask 后首次 DQN；reward = z + 0.1*hp_diff + 0.05*hand_diff
- **根因（用户实测）**：`_close_prev` 只算了**自己的** HP/hand diff，没减对手侧
  - 后果：摸牌 +0.10、出牌 −0.15、打掉对手 1 血 = 0 分
  - = 教它"少出牌、别掉血"→ 龟缩：对②(20%) > 对①(11%)，均轮 10.8 拖着不死
- **5万局零增长**（ep52000 tau=0.1 18.3% vs ep102000 tau=0.1 14.7%，CI 完全重叠=平台期）
- **结论**：reward 符号错，不是模型问题

## v2：reward 修复验证（重要正结果）

- **改动**：hp_diff 补对手侧（d_enemy = 敌人HP和减少为正）、删 hand 项、z 权重 1.0→2.0、tau 调度下限 0.3→0.1
- **结果（ep13000 离线评估，tau=0.1）**：对① 18.7% (CI 13.2-25.7)、对② 29.3% (CI 22.6-37.1)
- **对比 v1 ep102000（10.2万局）**：对① 14.7%、对② 21.3%
- **1.3万局就平/超 v1 的 10.2万局，对② 高 8pt** → output "学会了进攻"（旧 reward 打对手掉血 0 分）
- **注意**：tau 仍 1.0，还没收紧到利用态

## v3：显存卡死 + Q 尺度发现（两个教训）

- **卡死根因**：8GB 卡 + Windows 桌面共享显存（1-2GB），PyTorch 只剩 <400MB 余量，分配器踩边界 → WDDM 换页 → CUDA 内核死锁（py-spy 三次采样栈完全一致，~19min 无 checkpoint，GPU 99% 显存 7869/8188）
- **修复**：expandable_segments + bs 256→128（显存 7869→941MiB）
  - ⚠️ **注意**：本 PyTorch build 不支持 expandable_segments（platform unsupported 警告）——实际保护靠 bs=128
- **Q 尺度发现（用户 probe_qscale.py，84 决策点）**：
  - Q 极差 mean 0.583 / **median 0.158** / p10 0.084 / p90 0.785
  - **24 张候选牌分差只有 0.16 → tau=0.45 时 softmax 等价均匀采样**
  - 所以 tau 从 1.0→0.45 胜率纹丝不动（12.1→12.2）；"时间调度"全程无效
- **梯度步数发现**：66k 局 / update_every=200 = 330轮×16 = 5280 步 / 156min = **34 步/min**；游戏 476局/min 但学习只有 34步/min —— "不是 reward 不对，是根本没在学"

## v4：tau 固定 + 梯度密度修正（进行中）

- **改动**：update_every 200→25；current_tau 废弃时间调度 → tau_fixed（默认 0.1）
- **启动**：resume v3 ep66000 → 4h（后改 2h）--bs 128 --tau 0.1 --update-every 25
- **起步数据**（metrics.csv）：
  - ep1000/4min：对① 23%、对② 30%、loss 0.078
  - ep4000/16min：对① 稳定 23-24%、对② 33%、loss 0.11-0.13
  - 局速 ~250局/min、GPU 92%、显存 4.3GB（健康）
- **预期**：2h ≈ 1.5-2万梯度步（vs v3 的 5280）
- **注意**：ep<1000 时累计=近1k 是自然的；23% 是否持续/再涨需盯（可能部分受益 q_head 重初始化）

## 教训与纪律

1. **RL 观察指标第一位是梯度步数**，不是局数——34步/min 的"训练"不叫训练
2. **Q 尺度要实测**：softmax 训练前先 probe 极差，tau 必须 << Q 尺度才有区分度；"时间调度"在不理解尺度前无效
3. **reward 完整**：己方+对手侧 diff 都要算，缺一侧 = 教出反向行为
4. **显存边界**：8GB 卡 + Windows 桌面共享 = 常态危险，bs 减半比 allocator 配置可靠（本 build 不支持 expandable_segments）
5. 每版 checkpoint/metrics/eval 全保留 = 负结果基线（论文可引用）
## v5 总结 + 四条结论（2026-11-04）

### 1. n-step=3 保留（+6.3pt，幅度待噪声检查修正）
- 同协议对照（300局 tau=0.1 CPU）：v4 final 25.0% vs v5 ep59000 31.3%（对①）+6.3pt
- 对② +6.6pt、均轮 9.7→13.7 三信号同向 → n-step 真实有效
- 复现性检查：v5 ep59000 三 seed = 31.3/29.0/26.3 → 评估噪声带 ≈ ±2.5pt（5pt 跨度）
- +6.3pt > 2×噪声带 → 大概率真实；但版本差 <5pt 不算数（新规）

### 2. v4 真实水平 25-29%，"22% 平台"是训练窗口累计口径的假象
- v4 训练窗口累计 22% 是从随机 q_head 起、早期局拖低平均
- v4 终评 28.7%（第一次）/ 25.0%（重跑）→ 真实 25-29%
- v5 从 v4 终点续跑，累计口径自然 27% 起跳
- **教训：跨版本必须同口径终评，禁用训练窗口累计数**

### 3. 动作空间审计：只学选牌，不学选目标；特殊牌转规则 AI
- DQN use_phase_action 选目标是"座位序第一个合法目标"（写死打谁）
- equip/桃/无中/酒 直接转 opp._use_phased（规则 AI 兜底）
- **agent 能力边界：选牌靠 DQN，选目标靠座位序，特殊牌靠规则 AI**
- 27-31% 是"残缺动作空间"的天花板，不是 DQN 深度上限

### 4. 评估协议升级（最重要）
- 跨版本对比：必须同口径终评（300局 tau=0.1 同 seed 同池），禁用训练窗口累计
- 单次评估有 ±2.5pt 噪声（引擎全局 random 洗牌，seed 未完全控制）——报告时给噪声带
- 以后任何版本差 >5pt 才算差异；<5pt 报"噪声内"
- eval_greedy 需改进：引擎洗牌用独立 RNG（待办）

## 瓶颈重定位：缺"过"动作（2026-11-04 晚，用户三步）

### 核心事实：比基线差 19 点，不是离上限差 19 点
- 规则 AI 当地主（对 2 规则农民）：48%
- 我们的 DQN agent 当地主：29%
- agent 只在地主 use_phase 接管"选牌"，其余全交规则 AI（选目标=座位序写死、
  闪/桃/无懈/弃牌=规则 AI）→ 同一身体只换选牌，胜率掉 19 点 → 训出的选牌比手写规则差

### 第1步：自愿过牌率（规则AI地主200局，只加日志）
- 出牌阶段 16384，有合法牌可打 15896（97%）
- **有牌却过 4845 → 自愿过牌率 30.5%**（>25% → 加 pass 最高优先级 ✅）
- 无牌被迫过 456（3%）
- 结论：规则 AI 每 3 个出牌阶段主动忍 1 次（留杀/留桃/不交 AOE）；
  DQN 动作空间无 pass（有牌必打）→ 掉 19 点主因之一

### 第2步：钉死基线（纯规则AI当地主300局）

## pass 动作 R2：诊断 + 校准 + 配对评估（2026-11-04 夜）

### 教师不出率统计（标定目标值）
- 整体 31%（28386 决策）；有杀可打 21%、受伤有桃 24%、有进攻无杀 27%、只有装备 48%、其他 55%

### task B 纯模仿对照（判定 RL 方向）
- task B 纯模仿 8.3%（300局 seed101）vs v5 DQN 29% → **RL 有正贡献 +20.7pt（3.5倍）**
- 教师一致率 76%(taskB) → 30%(v5 q_head) = 模仿→价值导向的正常代价，价值导向赢了
- "回模仿+约束"路线排除

### 诊断 1（过牌集中在什么局面）：机制不成立
- pass 点 vs card 点 HP 完全相同（3.7）→ 不是"危险时更容易过"
- pass 点手牌更少（4.1 vs 4.8）→ 常数阈值按预期工作（没好牌才过）

### 诊断 2（每阶段出牌数）：空过阶段是关键
- 每阶段出牌 1.8→1.6（有 pass）
- **空过阶段（0 张）12%→20%**——吃掉胜率的是"空过阶段"不是"过牌决策"
- 目标应标定"空过率"（回合口径）而非"过牌率"（决策口径）

### 方案 D：二分直接解 pass_bias
- 只采**阶段首决策**点（621 个），二分使空过率=目标
- **pass_bias = -0.1894 → 空过率 12.1% ≈ v5 基线 12%**
- 采集 bug 教训：Probe 自决策会崩（每局 1 点）→ 只采集委托 base

### 配对评估脚本（sh 尺子校准，最重要产出）
- `src/train/paired_eval.py`：同牌双跑（setup 一次 deepcopy 两份含 rng → 各挂 strat）
- v5 vs v5 自评：diff +0.025, CI [-0.086,+0.136] 含 0（40 对就出结论）
- v5 vs pass_low：diff -0.020, CI 含 0 → pass 初值行为回基线 ✅
- 教训：独立评估 19%~31% 波动 12pt → 配对是以后所有 A/B 的唯一标尺
