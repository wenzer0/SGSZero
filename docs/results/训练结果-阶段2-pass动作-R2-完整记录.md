## 五、关键教训（写进纪律）

1. **标定对象选错是最隐蔽的坑**："过牌率 31%"(决策口径) vs "空过率 12%"(回合口径)——影响按回合算，目标必须用回合口径。判断标准："吃掉胜率的是空过阶段，不是过牌决策"
2. **配对评估是必要的尺子**：独立评估同策略波动 12pt（19%~31%），配对 40 对就出结论。**没有配对，每次 A/B 都在赌运气**
3. **冻结楼层的 warmup**：用交叉熵训整个 q_head 是错的（把价值头往模仿拖），只训 pass_bias（或解偏置）才干净；Spearman ρ（同状态前后对比）是"价值排序是否被洗"的正确度量
4. 教师的不出率 31% 是"教师选牌下的最优"，不能直接当我们的目标（刻舟求剑）

## 八、验收后补充记录（关机前最后落档）

1. **pass 显著有效**：配对 300 对，diff +7.3pt，CI [+0.016,+0.131]，t=2.51
2. **标定对象从"过牌率 31%"改成"空过率 12%"**——关键修正（影响按回合算，目标必须用回合口径）

### 待办（下次开机第 1 步）
- **均轮拆分**：赢局均轮 v5 vs v6 / 输局均轮 v5 vs v6
  - 赢局变长输局不变 → 聪明忍 → 直接 8h
  - 赢输都长 → 拖 → 查 pass 是否变"不敢打"
- **绝对胜率**：w(v5) 和 w(v6) 各多少（diff +0.073 看到了，缺两个绝对值，决定 8h 目标定在哪）
- **buffer 搬 CPU**（显存 6.2GB → ~1.5GB，防 8h 中途换页卡死）：
  - replay buffer 存 GPU 张量 ≈ 10.7KB/条 × 50万 ≈ 5.3GB 显存（v5 显存爬到 7.5GB 的根因）
  - push 存 CPU 副本，train_batch 搬回 dev；每批 128×10.7KB ≈ 1.3MB 传输可忽略
