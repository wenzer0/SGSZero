# 阶段 1 结论：argmax 塌陷

> 时间：2026-11-02
> 状态：已定稿，阶段 1 收尾
> 一句话：**监督学习学到的"最像教师"的那个选择，是整局胜率的塌陷点。**

---

## 一、问题

任务 A 在验证集上准确率 **80.9%**，任务 B 端到端 66.5%，但**整局对规则 AI 的胜率只有 44%**——低于随机基线 50%。

一个"80.9% 准确"的模型，为什么打得比瞎猜还差？

---

## 二、四条排除（逐一排除工程原因）

### 排除 1：环境 bug

| 检查 | 结果 |
|---|---|
| 执行率（动作真被执行的比例） | 71% → **100%**（修 can_use 后） |
| can_use 覆盖 | 5 种牌 → **全部牌** |
| jiedao 目标检查 | 缺 → 已补（目标无武器 10/10 拒绝） |
| legal_mask | 全 1（bug）→ can_use 现算 |

**结论：环境已干净，不是环境问题。**

### 排除 2：排序没有判断力

| 指标 | 值 | 判读 |
|---|---|---|
| top1−top2 概率差（中位） | **0.90** | 高度确信，不是并列 |
| 差距 >0.3 的占比 | 78% | 模型"有主见" |
| 差距 <0.1 的占比 | 15% | 少数犹豫 |

**结论：模型不是"按频率排"，它很确信。所以不是"没判断"，是"判断错了方向"。**

### 排除 3：牌型偏置（辅助牌过多）

实验：对辅助牌（桃/无中/装备/闪/无懈）在排序时降权 20%。

| 配置 | 胜率 | 均轮 |
|---|---|---|
| 基线 | 44% | 60.4 |
| 辅助降权 20% | **38%** | 60.4（没变） |

**结论：降权反而更差，且均轮完全没变 → 偏置不在"辅助 vs 进攻"这个轴上。辅助牌在某些局面是必需的。**

### 排除 4：价值函数 V(s) 有用

消融实验：训练 V(s) 重排 vs **随机初始化 V(s)** 重排。

| 组 | 胜率 | 均轮 |
|---|---|---|
| B'（训练 V 重排） | 66% | 8.3 |
| **C（随机 V 重排）** | **66%** | 8.0 |

**结论：随机 V 与训练 V 效果完全一致 → V(s) 没有贡献。提升来自"扩大候选集"本身，不是价值函数。**

---

## 三、四趋势实验（核心证据）

同源对比（top-N 随机采样，同一代码路径，各 100 局）：

| 配置 | 胜率 | 中位轮数 |
|---|---|---|
| top-1（argmax） | **44%** | 60.4（均值，中位数未记录） |
| top-2 随机 | 66% | 31 |
| top-3 随机 | 62% | 20 |
| top-5 随机 | 63% | 20 |

![argmax collapse](figures/argmax_collapse.png)

**两个形状：**

```
胜率：44 → 66 → 62 → 63      top-1 塌陷，top≥2 平台
中位轮数：60.4 → 31 → 20 → 20  单调下降，边际递减
```

**注意（易错点）**：早期表格中"top-3 = 8.3 轮"来自**另一条代码路径**（价值函数重排），与 top-N 随机不同源，不可混入同一曲线。混用会画出假的 V 型。

---

## 四、核心结论

> **锁死 argmax 就塌陷（44%，低于随机）。任何形式的容错——top-2 以上随机、或从分布中采样——都能恢复到 62-66%。**

**机制解释：**

```
模型与教师一致率 76%，top-3 包含教师 99%
→ 模型"知道"正确答案在候选里
→ 但"硬取最大值"锁死了最像教师的那一张
→ 而"最像教师" ≠ "最优"（教师自己也只有 58% 胜率）
```

**为什么"最像教师"会差：**

教师出辅助牌时很确定（装装备几乎每次都这样），出进攻牌时经常犹豫（看血量、看手牌、看该不该留）。交叉熵训练让模型学到"辅助牌置信度高"，于是排序系统性偏向辅助牌——**学到了教师的犹豫，却没学到教师判断的依据。**

---

## 五、对下一步的启示

### 5.1 必须换目标，不是修参数

四条排除 + 四趋势指向同一个结论：**"模仿教师"这个目标本身到不了"赢"。**

- 不是模型能力不够（80.9% 准确率）
- 不是数据不够（13,536 条）
- 不是环境有 bug（已全修）
- 是**目标函数错位**

### 5.2 RL 的正确形态：学分布，不是学 argmax

| 做法 | 结果 |
|---|---|
| 硬 argmax | 44%（塌陷） |
| 随机 top-N | 62-66%（平台） |
| **学一个分布，从中采样** | **应当 ≥ 平台，且更果断** |

**所以 RL 阶段的关键设计：**

```
q = critic(state, candidates)
probs = softmax(q / tau)
action = sample(probs)          ← 不是 argmax
```

**tau 不能太小**（太小会退化成 argmax，重蹈塌陷）。

### 5.3 论文价值

这个发现比"某模块提升 X 个点"值钱得多，因为它是一个**可推广的结论**：

> 在"从专家数据学习"的场景里，模仿的 argmax 是性能上限的塌陷点；正确做法是学习一个分布，保留候选集的容错性。

**适用于任何 imitation learning 场景，不限于三国杀。**
