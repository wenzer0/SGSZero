# 部署一致性检查清单（系统性风险防护）

> 背景：本项目已因"训练/部署不一致"出过 2 次 bug（deck 桶、legal_mask），
> 这是最高频的 bug 类型。每次部署（改部署代码、加新任务、重训模型）前 10 分钟跑一遍。

## 检查项

- [ ] **tokenizer 版本一致**：部署用同一个 tokenizer 文件、同一份 vocab.json（不是"看起来像"的副本）
- [ ] **词表 hash 相同**：部署 vocab 与训练 vocab 的 md5/sha 一致（防止 build 顺序/内容漂移）
- [ ] **状态编码逐 token 对齐**：抽 100 条，逐 token 对比"引擎输出的 state 编码" vs "训练数据编码"（gate_encoding.py 已实现）
- [ ] **legal_mask 用同一个 can_use 函数**：部署时 mask = 引擎 can_use 现算，不是全 1 默认（本次 bug 根因）
- [ ] **动作格式一致**：action[0] 的 token id 语义与训练一致（ACT_USE 等）
- [ ] **模型输入维度一致**：tokens 长度上限、hand_pos/max_hand、self_pos 位置与训练一致
- [ ] **deck 分桶用同一个 _deck_bucket**：部署推理时 deck 也必须过同一个分桶函数（第一次 bug 根因）
- [ ] **先报执行率再报胜率**：任何实验报告第一行 = 执行率%（>95% 才继续看胜率）

## 每次部署前 10 分钟跑

1. `python engine/gate_encoding.py --n 100`（编码逐 token 对齐）
2. 执行率审计（audit_exec2.py 思路）：B 选出 → 引擎真打出 命中率 >95%
3. 若任一不过 → 停下，先修，不进入胜率对比
